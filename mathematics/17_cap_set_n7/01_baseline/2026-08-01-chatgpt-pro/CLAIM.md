# Claim

**Claim.** 236 <= a(7) <= 291, where a(7) is the maximum size of a cap (line-free set) in AG(7,3). Lower bound: an explicit 236-point cap (`cf236.csv`). Upper bound: an exact hyperplane-moment certificate ruling out a 292-cap, conditional on a(6)=112. This is a reproduction of known results, not a frontier improvement: the literature already gives 236 <= a(7) <= 288 (arXiv:2206.09804, no-289-cap claim). No cap larger than 236 was found, and no proof of a(7) <= 290 was completed.

**Checker.**
- Lower: `python3 src/verify_triples.py cf236.csv` scans all 2,162,940 triples for a zero-sum. Re-run 2026-08-01: `PASS triple-scan: n=7 size=236`. Independent C++ line checker: `src/verify_lines.cpp`.
- Upper: `src/verify_upper_291.cpp` (independent C++) reconstructs the 184 profiles, moment totals, slack partition, and mod-645 contradiction. Re-run 2026-08-01: `PASS ... a(7)<=291`. Python generator/checker: `src/certify_upper_291.py`.
- Toolchain: Python 3.12, g++ -std=c++17 -O2. Pin exact versions before archival.

**Trust base.** Exact integer arithmetic only, no floating point. The upper bound assumes the published theorem a(6)=112 (Potechin), not re-proved here: a 112-cap was built and checked, but the no-113-cap computation was not reproduced. No custom axioms or oracles.

**Encoding fidelity.** A cap is a subset of F_3^7 in which no three distinct points sum to 0 mod 3 (equivalently, no affine line lies in the set). `cf236.csv` is the witness; `verify_triples.py` checks exactly this. See the report's two formulation corrections: in characteristic 3, x+y+z=0 with two coordinates equal forces all three equal, and the cap test is `-x-y not in C`, which is weaker than a Sidon condition.
