### Abstract

Resolution is the proof system underlying every CDCL SAT solver, and the minimum size of a resolution refutation of an unsatisfiable CNF is a genuine, well-posed optimization with a rich lower-bound theory (Haken's pigeonhole bound, the Ben-Sasson–Wigderson width–size relation, feasible interpolation). It is also unusually machine-friendly: modern SAT solvers *emit* resolution/DRAT proofs whose correctness an independent checker verifies clause-by-clause, giving certified *upper* bounds directly, while the minimum *width* of a refutation is exactly computable in polynomial time and lower-bounds size. The certifiable product is a table of certified minimum (or tightly two-sided) resolution refutation sizes and exact minimum widths for canonical small instances - pigeonhole \(\mathrm{PHP}^m_n\), Tseitin formulas on small graphs, and random 3-CNF near the threshold - each with a checked proof and a lower-bound certificate. The on-machine verifier is a DRAT/LRAT checker plus an exact width computation. A solver run reported without a checked proof, a minimum-size claim with no matching lower bound, or an asymptotic bound where an exact small value is asked, is a partial result.

## 1. Exact problem statement

A **CNF** \(F\) is a set of clauses over variables \(x_1,\dots,x_n\); \(F\) is **unsatisfiable** if no assignment satisfies all clauses. A **resolution refutation** of \(F\) is a sequence of clauses \(C_1,\dots,C_L\) with \(C_L=\bot\) (the empty clause), each \(C_i\) either a clause of \(F\) or the **resolvent**

\[
\frac{A\vee x \qquad B\vee\overline{x}}{A\vee B}
\]

of two earlier clauses. The measures of a refutation \(\pi\) are:

- **Size (length)** \(|\pi|=L\), the number of clauses (the standard size measure);

- **Width** \(w(\pi)=\max_i |C_i|\), and the **refutation width** \(w(F\vdash\bot)=\min_\pi w(\pi)\);

- **Tree-like** versus **general (DAG)** resolution: in tree-like resolution each derived clause is used at most once. Write \(\mathrm{Res}(F)\) for minimum general size and \(\mathrm{Res}^\*(F)\) for minimum tree-like size.

**Adopted measures.** Primary target: minimum **general** resolution refutation size \(\mathrm{Res}(F)\) (number of clauses). Companions, reported separately: minimum **tree-like** size \(\mathrm{Res}^\*(F)\) and minimum **width** \(w(F\vdash\bot)\) (exactly computable, and a size lower bound). The measures satisfy

\[
w(F)\ \le\ w(F\vdash\bot),\qquad \mathrm{Res}(F)\ \le\ \mathrm{Res}^\*(F),\qquad \mathrm{Res}^\*(F)\ \le\ 2^{\,O(n)},
\]

where \(w(F)\) is the initial clause width. Size counts clauses; variants (counting only resolution steps) are noted and converted.

**Named target formulas.**

1. **Pigeonhole** \(\mathrm{PHP}^m_n\): \(m\) pigeons, \(n\) holes, \(m>n\); each pigeon in some hole, no two pigeons share a hole. Small \((m,n)=(n{+}1,n)\), \(n=2,3,4,\dots\).

2. **Tseitin** \(\mathrm{Ts}(G,\sigma)\): a graph \(G\) with a charge \(\sigma\); parity constraints per vertex, unsatisfiable when \(\sum_v\sigma(v)\) is odd. Small graphs (grids, small expanders, complete graphs).

3. **Random 3-CNF** at the satisfiability threshold (clause density \(\approx4.267\)) on small \(n\), conditioned unsatisfiable.

**The exact question (adopted here).** For a named unsatisfiable \(F\), determine \(\mathrm{Res}(F)\) (and \(\mathrm{Res}^\*(F)\), \(w(F\vdash\bot)\)) **exactly** - the least number of clauses in a refutation, with a matching impossibility for one fewer.

**Starting from the prompt alone.** Each formula is generated by an explicit rule; a reader writes its clauses, checks unsatisfiability, checks any candidate refutation clause-by-clause (each line an input clause or a valid resolvent, ending in \(\bot\)), and counts clauses - so the upper-bound object and the search are reconstructable.

## 2. Resolution standard

An exact \(\mathrm{Res}(F)\) is resolved only in **certified two-sided** form:

- **Upper bound:** an explicit resolution refutation of size \(s\), serialized, replayed by an independent checker that verifies every line is an input clause or a sound resolvent and that the last clause is \(\bot\) - equivalently a **DRAT/LRAT proof** run through `drat-trim`/`lrat-check`, with clause count \(=s\) (RUP steps mapped to resolution steps where the comparison is size-faithful).

- **Lower bound (certified core):** either (a) a **DRAT-checked UNSAT** proof of the SAT/ILP encoding "there exists a resolution refutation of \(F\) of size \(\le s-1\)", establishing \(\mathrm{Res}(F)\ge s\); or (b) an **exact width lower bound** \(w(F\vdash\bot)=w\) (computed exactly) fed through the Ben-Sasson–Wigderson relation

\[
\mathrm{Res}(F)\ \ge\ \exp\!\Big(\Omega\big((w(F\vdash\bot)-w(F))^2/n\big)\Big);
\]

or (c) an exact feasible-interpolation / bottleneck-counting certificate where applicable.

Named certified form: **a DRAT/LRAT-checked refutation for the upper bound, paired with either a DRAT-checked lower-bound-encoding UNSAT or an exact minimum-width computation for the lower bound.**

**Not accepted as resolution.**

- A SAT-solver run reported as a "proof size" without a checked DRAT/LRAT proof, or with a proof the independent checker rejects.

- A refutation (upper bound) with no matching lower bound presented as the *minimum* size.

- An asymptotic bound (Haken's \(2^{\Omega(n)}\), or the width–size exponent) reported as the *exact* small-case value - asymptotics never give the exact clause count.

- A DRAT proof whose steps are not size-faithfully mapped to resolution: RAT/extension steps can be shorter than any resolution proof, so the comparison must be to a resolution-only or verified-resolution proof, and any extension step must be flagged as a *different* system.

- Conflating \(\mathrm{Res}\), \(\mathrm{Res}^\*\), and width - each is a separate certified value.

- A random-3-CNF instance reported without its generation seed and unsatisfiability filter, so the instance cannot be regenerated bit-for-bit.

- An unreplayable run: formula generator, encoding, solver version, and proof not preserved.

## 4. Known results and prior art

- **Pigeonhole lower bound.** Haken (\(\approx\)1985, verify): \(\mathrm{Res}(\mathrm{PHP}^{n+1}_n)=2^{\Omega(n)}\), the first exponential resolution lower bound. Preceded by Tseitin's (\(\approx\)1968, verify) superpolynomial regular-resolution bounds.

- **Width–size relation.** Ben-Sasson–Wigderson (\(\approx\)2001, "Short proofs are narrow - resolution made simple," verify): a uniform route to most resolution lower bounds via width. Width–size trade-offs for PHP specifically (verify). Note PHP's own width bound needs care (the general relation does not apply cleanly - verify).

- **Tseitin formulas.** Urquhart (\(\approx\)1987, verify): exponential resolution lower bounds for Tseitin on expanders; Ben-Sasson–Wigderson recover these via width. Exponential bounds for weak PHP and sparse-graph matching (arXiv 1912.00534, verify).

- **Random \(k\)-CNF.** Chvátal–Szegedy (\(\approx\)1988, verify) and Ben-Sasson–Wigderson: exponential resolution size for random 3-CNF just above the threshold (density \(\approx4.267\), verify).

- **Width is computable; size is hard.** Minimum refutation width is computable in \(n^{O(w)}\) (Ben-Sasson–Wigderson dynamic programming, verify). Determining/approximating minimum resolution *size* is computationally hard (Alekhnovich–Razborov and Atserias–Müller hardness of automatizability, \(\approx\)2001/2019, verify) - hence exact size is a small-instance target, not a general algorithm.

- **Feasible interpolation.** Krajíček's feasible-interpolation method (\(\approx\)1997, verify) yields resolution size lower bounds for formulas with a suitable clause split, an alternative to width for certain small instances (record the exact hypotheses used, verify).

- **Certified proofs and checkers.** DRAT is the standard SAT proof format (Wetzler–Heule–Hunt, \(\approx\)2014, verify); `drat-trim`, `lrat-check`, and formally verified checkers (`cake_lpr`, verify) close the loop. "Finding bugs in short proofs / the metamathematics of resolution lower bounds" (arXiv 2411.15515, verify) is recent context.

## 5. Attack plan

**`[cert]` - certified upper bounds via solvers.** Generate each instance; run CDCL solvers (`kissat`/`CaDiCaL`/`CryptoMiniSat`) with DRAT logging; check every proof with `drat-trim`/`lrat-check` (and a formally verified checker where possible). Record proof size as a certified upper bound on \(\mathrm{Res}\); minimize by proof-trimming and by trying multiple solvers/variable orderings.

**`[cert]`/`[search]` - exact width.** Implement the exact minimum-refutation-width algorithm (bounded-width saturation / the reachability characterization); it is polynomial for bounded width and gives a certified size lower bound through the width–size relation with explicit constants.

**`[search]` - exact minimum size for the smallest instances.** Encode "there is a resolution refutation of \(F\) with \(\le s\) clauses" as SAT/ILP: variables for a sequence of \(s\) clauses, each an input clause or a sound resolvent of two earlier ones, ending in \(\bot\); binary-search \(s\). The least SAT \(s\) is \(\mathrm{Res}(F)\); the UNSAT at \(s-1\) - **DRAT-checked** - is the lower bound. Use tree-like DP for \(\mathrm{Res}^\*\).

**`[cert]` - cross-checking upper bounds.** Where two solvers or two variable orderings yield refutations of different sizes, keep the smallest DRAT-checked one as the certified upper bound and record the spread; a proof-trimming pass (`drat-trim -f`) removes unused lemmas before the size is read off.

**Tools.** `kissat`/`CaDiCaL`/`CryptoMiniSat` + DRAT; `drat-trim`/`lrat-check`/`cake_lpr`; custom C++ for generators, the width algorithm, and the size-encoding; `SCIP`/`SoPlex` exact for ILP variants; `SageMath`/`nauty` for Tseitin graph generation.

**One-workstation scope.** DRAT upper bounds for PHP/Tseitin up to moderate \(n\): routine (proofs can be large); exact width for small width: feasible; exact \(\mathrm{Res}\) via the size-encoding: only the very smallest instances (\(\mathrm{PHP}^3_2,\mathrm{PHP}^4_3\), Tseitin on \(K_4\)), the size-encoding blowing up fast.

**Failure modes.** DRAT proofs with RAT/extension steps are *not* resolution proofs - their length can beat any resolution refutation, so size comparisons must be to verified-resolution proofs only; a solver "UNSAT" without a checked proof is not a bound; the size-encoding's clause count is \(\Theta(s^2\cdot n)\) and explodes; width and size are different measures and the width–size relation is one-directional; PHP needs care with the width bound.

## 6. Verification and auditability requirements

1. **Exact or certified computation.** Every upper bound is a DRAT/LRAT-checked refutation with a size-faithful mapping to resolution; every lower bound is either a DRAT-checked size-encoding infeasibility or an exact, independently recomputed minimum width fed through the width–size relation with explicit constants. No claim rests on an unchecked solver run.

2. **Independent verification.** A standalone resolution-line checker (each line an input clause or sound resolvent, terminating in \(\bot\)) re-validates each refutation independently of the solver; a formally verified DRAT/LRAT checker validates the proofs; the minimum-width computation is recomputed by a second implementation; a second solver re-derives headline upper bounds.

3. **Reproducibility.** Formula generators and their parameters (PHP \((m,n)\); Tseitin graph + charge; random-CNF seed, density, and unsatisfiability filter), CNF encodings, solver/checker versions, and the size-encoding are recorded; a SHA-256 manifest covers every CNF, proof file, and width certificate; any prior exact size/width being matched or improved is cited with source and access date.

4. **Preservation.** Generators, the width algorithm, the size-encoding, all proof files, and checker logs are part of the record; large DRAT proofs are retained or their loss stated explicitly.

5. **Honest reporting.** The report states, per formula and per measure (\(\mathrm{Res}\), \(\mathrm{Res}^\*\), width), whether the value is exact (two-sided certified), a certified bracket, or only an asymptotic bound; it distinguishes resolution-only proofs from DRAT-with-extension proofs; and it never presents a single solver's proof size as the *minimum* resolution size, nor an asymptotic lower bound as an exact small-case value.
